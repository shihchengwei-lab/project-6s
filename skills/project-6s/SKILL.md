# 專案 6S

交付可維護、可驗證的最新狀態。檔案完整不等於資訊有效；不要用「保存完整／歷史脈絡」把髒資料留下來污染模型上下文。

## 先定義範圍與停止條件

- 讀適用的協作規則與現行文件，檢查工作目錄、未提交變更及使用者指定範圍。可處理整個專案，或只處理測試、文件、素材。
- 簡短說明這次會整理什麼、哪些行為須保持，以及如何驗證；不為可自行查明的細節反覆詢問。
- 使用現成的建置、測試與資產清單。發現問題先選一個具體案例處理並驗證，再處理同類問題；不要只列清單而不動手。
- 不以刪除數量、測試數量或縮減比例當目標。不順便展開功能開發、廣泛重構或安全稽核。

## 最新狀態與封存邊界

- 現行文件只留仍有效的操作、設計、限制及未完成事項。直接改寫被取代的段落，刪掉已完成待辦；不要用追加更正讓多代狀態並存。
- 不自動建立交接副本、過程報告、變更前全文、落選圖集或稽核資料庫。清理的證據優先在回覆中交代，不再生成另一批髒資料。
- 確有法定、維運、回復用途或使用者要求保存時才封存；不要把刪除候選一律改成封存候選。
- 必要封存優先放在工作區之外的明確位置，或既有的獨立封存服務。封存可能含私密資料，不自行上傳公開服務。位置未明且會影響處理時，先完成其他清理，再針對該批資料釐清。
- 若指定必須留在專案內，使用既有檢索／代理設定明確排除封存，日常文件不內嵌、不預載其內容；不能只加 history/ 名稱或 .gitignore 就宣稱已隔離。無法控制檢索邊界時如實說明。
- 現行建置與維護不得依賴封存。刪除或封存前，將仍必要的來源歸入正式位置並更新引用。封存不是現況依據。
- 專案既有保存要求與當次使用者指示一起判斷；不要自行修改協作規則以取得刪除授權。

## 六項作業

| 項目 | 實際動作 |
|---|---|
| 整理 | 按使用用途、引用與重建能力分類；刪除確認無用的中間檔、過期副本及落選素材。未被程式引用不代表無用，另查人工流程、授權與正式原稿。 |
| 整頓 | 正式來源固定位置與命名；同一事實只保留一個權威來源，其他內容衍生或連結。先解除對舊產物的依賴，再移除它。 |
| 清掃 | 修正失效引用、重複設定與過期描述；依行為契約整理測試，避免只照抄實作。 |
| 清潔 | 合併重複文件，讓操作、設計與現況各有清楚歸屬。保留有實際用途的決策理由，不保留逐輪對話與已廢棄方案。 |
| 素養 | 執行與變更相關的檢查；只有能防止實際復發時，才加入簡單的現有檢查約束，不新增通用清理框架。 |
| 安全 | 刪檔前核對絕對路徑、專案邊界與符號連結；保護必要授權、正式來源、玩家／使用者資料及無關未提交工作。 |

涉及測試整理時，讀 [test-cleanup.md](references/test-cleanup.md)；其他情況不用載入。

## 驗證與收尾

- 驗證實際風險：引用修正後來源可讀、清理後可正常建置、改寫的測試仍能抓到對應錯誤。保留原有必要門檻，不用 skip、放寬條件或改期望值掩蓋失敗。
- 必須重建才能驗證時，說明這是清理驗證；使用隔離的暫存輸出，不自動重新上傳已發布產品。檢查結束清除自己產生的輸出、臨時腳本與快取；不擴大清除共用環境或正在使用的服務。
- 檢查不過時先判定是清理損壞、既有問題還是環境限制。能在範圍內修正就處理；其餘具體列出，不宣稱全部完成。
- 最後用接手者視角，只讀現行文件定位入口與來源，執行一條代表性操作；確認不必回頭讀封存，也沒有失效路徑。這不等於獨立模型接手測試，勿混稱。
- 完成條件：指定範圍已處理、必要來源完整、行為及引用有效、文件對齊現況、驗證產物清乾淨。沒有剩餘相關問題就停止，不無限擴大盤點。
- 依使用者語言簡潔回報六項各做了什麼、有效檢查與未驗證界線；數量只作觀察結果。
- commit、push、部署或發布依另外的使用者指示執行；6S 本身不包含這些外部動作。
