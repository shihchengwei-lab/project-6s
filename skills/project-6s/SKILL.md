# 專案 6S

依使用者指定的範圍整理專案，讓接手者能從現行文件找到正式來源、執行必要操作。

## 確認範圍

- 讀協作規則與現行文件，檢查工作目錄和未提交變更。簡短說明整理範圍、要維持的行為與驗證方式。
- 依使用者指示與文件用途選定版本，例如已發布版或開發版。從本次變更的實作、規格或驗證結果追查哪些現行文件引用或轉述它們，將受影響的內容和核對依據納入整理範圍。
- 沿用既有建置、測試與資產清單。遇到同類問題時，先處理並驗證一個代表案例，再套用到其餘項目。
- 提交、推送、部署與發布依使用者指示執行。

## 處理舊副本與產物

搬移或刪除前，先做下表的安全檢查。

1. **確認正式來源並歸位。** 核對程式引用、人工流程、授權、原稿用途與重建方式，辨認仍需維護的來源，確立其位置與命名。
2. **更新依賴。** 將建置、維護流程與現行文件仍需使用的引用指向正式來源，並按選定版本更新受影響的文件內容。確認舊檔已無現行依賴，再決定去向。
3. **刪除或封存。**
   - 刪除已確認無用且允許移除的舊檔。
   - 因法定、維運、復原需求或使用者指示而須保存的資料，封存於工作區外或既有獨立封存服務，並核對存取權。封存若須留在專案內，用既有設定排除日常搜尋與模型讀取。
   - 用途或授權待確認，或需要封存但位置未定時，保留該批資料，繼續其他清理。
4. **從現行入口驗證。** 依[收尾步驟](#驗證與收尾)驗證受影響的操作。封存留在專案內時，另從日常搜尋與模型讀取的入口驗證隔離，回報仍能讀到封存或待查的入口。

## 六項 6S 檢查表

依本次範圍核對相關項目。

| 項目 | 檢查問題 |
|---|---|
| 整理 | 無用的中間檔、過期副本與落選素材已處理？ |
| 整頓 | 每項資訊都有固定位置與單一維護來源？ |
| 清掃 | 失效引用與重複設定已修正？測試涵蓋要維持的行為？ |
| 清潔 | 文件已合併重複內容、改寫過期段落、移除完成的待辦，並保留仍有效的操作、設計、限制與決策理由？ |
| 素養 | 已沿用現有檢查？新增的規則能防止已辨認的問題復發？ |
| 安全 | 搬移或刪除前，已核對絕對路徑、專案邊界、符號連結的目的地、保存規則及當次授權？已保護授權文件、正式來源、使用者資料與無關的未提交變更？ |

涉及測試整理時，讀 [測試 6S](references/test-cleanup.md)。

## 驗證與收尾

- 逐份用選定版本的來源核對受影響的文件內容。完整案例回答要與同版結果一致，摘要及翻譯要保留會改變判斷的條件。有差異就修正，仍待查證的項目列為未完成。依現行文件找到正式來源，按選定版本跑一項受影響的代表操作。
- 跑受影響的建置與測試，沿用既有通過條件。需要重建時，將輸出放在隔離位置。檢查失敗時定位原因，修復本次範圍內的問題。
- 清除本次驗證產生的臨時輸出、腳本與快取。
- 回報實際改動、驗證結果，以及仍會影響使用或接手的問題。需要核對時，附上既有紀錄的位置。
