# 專案 6S

依使用者指定的範圍整理專案，讓接手者能從現行文件找到正式來源、執行必要操作。

## 確認範圍

- 讀協作規則與現行文件，檢查工作目錄和未提交變更。簡短說明整理範圍、要維持的行為與驗證方式。
- 沿用既有建置、測試與資產清單。遇到同類問題時，先處理並驗證一個代表案例，再套用到其餘項目。
- 提交、推送、部署與發布依使用者指示執行。

## 六項作業

| 項目 | 實際動作 |
|---|---|
| 整理 | 核對程式引用、人工流程、授權、原稿用途與重建方式，刪除確認無用的中間檔、過期副本及落選素材。 |
| 整頓 | 為正式來源固定位置與命名。同一份資訊由單一來源維護，其他位置引用它。移除舊產物前，先把必要來源歸位並更新依賴。 |
| 清掃 | 修正失效引用與重複設定，整理測試，使每個案例驗證它要守住的行為。 |
| 清潔 | 合併重複文件，直接改寫過期段落，移除已完成待辦。保留仍有效的操作、設計、限制、決策理由及待辦。 |
| 素養 | 沿用現有檢查。有明確復發風險且檢查能攔下時，才加入對應規則。 |
| 安全 | 刪除或搬移前核對絕對路徑、專案邊界及符號連結的目的地。依既有保存規則和當次授權處理，保護授權文件、正式來源、使用者資料及無關的未提交變更。 |

涉及測試整理時，讀 [測試 6S](references/test-cleanup.md)。

## 封存

- 有法定、維運或復原用途，或使用者指定保存時才封存。優先使用工作區外的位置或既有的獨立封存服務，確認存取權符合資料性質。封存位置未定時，先完成其他清理，再確認該批資料的去向。
- 必須留在專案內時，用既有設定排除封存，並透過日常搜尋與模型讀取的入口驗證隔離。回報仍可讀到封存或無法查驗的入口。
- 封存前確認建置、維護與現行文件所需的來源都在正式位置。

## 驗證與收尾

- 檢查受影響的引用、建置或行為，沿用必要的通過條件。若必須重建，使用隔離的輸出位置。檢查失敗時，查明是本次變更、既有問題或環境限制，修復範圍內的問題。
- 從現行文件找到入口與來源，執行一項代表性操作，確認過程中的連結有效且來源齊全。清除本次驗證產生的臨時輸出、腳本與快取。
- 指定範圍整理完畢且受影響的操作通過驗證即可收尾。回覆交代實際改動、驗證結果及仍會影響使用或接手的問題，必要時指出既有紀錄的位置。
